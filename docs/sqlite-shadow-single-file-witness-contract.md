# Single-file witness: private static draft

Status: untested, unintegrated and observational only. P7 HOLD applies. This component does not certify or authorize reads. It does not open paths or establish root containment, provenance, read-only OS access, share mode, writer exclusion, an atomic snapshot, or continuity. The caller must separately obtain an approved synthetic ordinary file and an already-open, read-only, unbuffered binary `io.FileIO` with no other offset consumer. Exact type avoids callbacks from subclasses and fake streams; `mode == "rb"` is a wrapper property, not proof of underlying OS access. No native Windows file ID, reparse handling or path identity is implemented. The handle is caller-owned and never closed or written by this module.

`observe_single_file(handle, max_size)` accepts a strict positive `int` excluding `bool`. It refuses other handles, nonregular descriptors and sizes over the bound. `fstat` supplies device, inode, mode, regular flag, size and nanosecond timestamps where available; absent values are listed, zero device or inode makes identity unproven, and all observations identify provenance, native identity, ancestry and timestamp continuity as untrustworthy. `ctime` meaning varies by platform. These values are not authenticated FileIdInfo. Unsupported required metadata yields UNPROVEN.

The offset must initially be zero. With exclusive use of the offset, two passes each read the initial size in chunks of at most 65,536 bytes plus a one-byte end probe, hashing actual bytes; no content is returned or persisted. The first-pass `byte_count` and second-pass `second_byte_count` count only successfully returned payload bytes, including progress before a later raised read; a one-byte excess probe is **not** a payload byte and is recorded separately as `first_probe_count` or `second_probe_count` (0 or 1). Thus an excess-byte refusal reports `byte_count == initial.size` and `first_probe_count == 1`, and total successful bytes returned for that pass equals their sum. The completed-pass digest excludes the probe. No incomplete digest is asserted. Each count and digest is separate from stat size. Short reads, excess data, differing hashes and differing endpoint metadata refuse. A complete pass digest is retained even when the other pass fails. Final same-descriptor metadata is attempted after the initial snapshot on every path. Equal endpoints do not establish that intermediate changes did not occur. The one-byte probe can observe growth beyond the bound but no bulk allocation exceeds a chunk. A concurrent user of the offset invalidates the precondition and may cause missed or misleading observations. A read or seek advances the shared OS offset; on completion it is at EOF after the second probe, and on failure its position is unspecified. The function does not restore it; even a refused position check leaves it unchanged. On Windows, descriptor operations use the CRT; no stronger share or identity guarantees are inferred.

Expected `OSError`, `ValueError` and `OverflowError` from descriptor operations yield UNPROVEN with exception class in the reason; final-stat failure also yields UNPROVEN unless an earlier refusal is retained. Unexpected exceptions propagate, with the final stat attempt made when applicable. Expected `os.read` exceptions are caught inside the pass helper, which returns the number of payload bytes successfully returned before the failure; the failed pass has no digest. A failed excess-byte probe preserves the full payload count but no completed-pass digest. This counts bytes returned to the observer, not bytes whose read was attempted or any data consumed by another offset user. The separate `final_stat_error` field records an expected final `fstat` exception even when an earlier `REFUSE` is the primary outcome; for a prior `UNPROVEN` reason it preserves that reason, and for a previously successful observation it changes the status to `UNPROVEN`. Unexpected exceptions still propagate. Initial and final metadata, differences and complete digests are retained where available. Metadata mismatch takes refusal precedence and appends to an earlier reason. A successful result is `OBSERVED_UNATTESTED`, never a production gate. `REFUSE` denotes a detected incompatible condition, `UNPROVEN` an unavailable observation; opaque provenance is always recorded.

Two matching passes cannot detect unobserved A-B-A, replacement of a pathname while the held handle still refers to the old object, writable aliases, hostile writes or any SQLite side effects. A visible change can still be missed. These limitations apply even to OBSERVED_UNATTESTED. No receipt, repair or filesystem mutation is performed.

W04 observed replacement is REFUSE; an intervening replacement not observed remains UNPROVEN. W11 an observed noncooperative writer is REFUSE; writer exclusion not established is UNPROVEN. These are conceptual mappings; this component checks neither receipts, names nor writers.
